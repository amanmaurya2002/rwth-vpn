# Releasing

## One-time setup

1. Create the repository and push `main`.
2. Optional but recommended — stable signing identity:

   ```bash
   ./scripts/make-signing-cert.sh "RWTH VPN Releases"
   ```

   Then add two repository secrets:

   | Secret | Value |
   |---|---|
   | `SIGN_P12_BASE64` | `base64 -i build/signing/identity.p12` |
   | `SIGN_P12_PASSWORD` | the `.p12` password (`rwth-vpn` by default) |
   | `SIGN_IDENTITY` | `RWTH VPN Releases` |

   Without these the release workflow builds an ad-hoc signed app and users get
   a Keychain prompt after every update.
3. Set the GitHub owner/repository links in `Sources/AppInfo.swift`.
4. Enable GitHub Actions and (optionally) branch protection on `main`.

## Website (GitHub Pages)

The landing page is `docs/index.html` (no build step, no Jekyll — `docs/.nojekyll`
is present). Enable it once:

1. Repository **Settings → Pages**.
2. **Source:** *Deploy from a branch*.
3. **Branch:** `main`, **folder:** `/docs`, then **Save**.

It is served at `https://<owner>.github.io/<repo>/`. The page derives the
repository from the URL, with the project owner as a safe fallback for custom
domains. Update screenshots with:

```bash
"dist/RWTH VPN.app/Contents/MacOS/RWTHVPN" --render-preview docs/
```

## Every release

1. Bump the version in `Resources/Info.plist` (`CFBundleShortVersionString`,
   `CFBundleVersion`).
2. If the helper CLI or the bundled payload changed, bump
   `Resources/helper-version.txt`.
3. Update `CHANGELOG.md`.
4. Build and test locally:

   ```bash
   ./build.sh --revendor
   "dist/RWTH VPN.app/Contents/MacOS/RWTHVPN" --selftest
   ./scripts/test-bundled.sh
   ```

5. Manual QA (the parts tests cannot cover):
   - [ ] Fresh download: DMG opens, app drags to Applications
   - [ ] macOS 26+: Open Anyway flow works, app launches
   - [ ] Helper install with admin prompt; connect succeeds
   - [ ] Disconnect restores DNS and routes (`scutil --dns`, `netstat -rn`)
   - [ ] Sleep/wake, then reconnect
   - [ ] Full tunnel connects; split tunnel leaves local network reachable
   - [ ] Uninstall removes helper, payload and sudoers rule
6. Commit, tag, push:

   ```bash
   git add -A && git commit -m "Release v1.0.0"
   git tag -s v1.0.0 -m "v1.0.0"
   git push && git push --tags
   ```

7. The `Release` workflow builds the DMG, zip and `SHA256SUMS.txt` and attaches
   them to the GitHub release. Verify the artefact names and download one DMG
   yourself.

## In-app updates

The app checks the latest GitHub release through the GitHub API. When an update
is available, it downloads the ZIP and `SHA256SUMS.txt`, verifies the ZIP's
SHA-256 digest, then replaces the running app and relaunches it. Keep the ZIP
and checksum asset names generated by the release workflow unchanged.

## CLI distribution

The release workflow also publishes `rwth-vpn-cli-<version>.tar.gz`, containing
the CLI and its helper resources.

The recommended installation method is the Homebrew-free installer:

```bash
curl -fsSL https://raw.githubusercontent.com/amanmaurya2002/rwth-vpn/main/install.sh | bash
```

It downloads the latest CLI archive, verifies `SHA256SUMS.txt`, and installs to
`~/.local/bin`. After installation, `rwth-vpn setup` installs the privileged
helper and `rwth-vpn connect` uses credentials shared with the app.
Installed users can update in place with `rwth-vpn update`; `rwth-vpn update
--check` checks without downloading.

`rwth-vpn uninstall` removes the helper and CLI; credentials remain unless
`rwth-vpn uninstall --purge` is used.

## Versioning

- App: semantic versioning in `Info.plist`.
- Helper/payload contract: `Resources/helper-version.txt`, bumped whenever the
  helper CLI or the bundled openconnect build changes.
- `VERSIONS.txt` inside the app records the exact Homebrew versions bundled.

## Rolling back

Releases are immutable tags. To undo a bad release, publish a new patch version
and mark the old one as pre-release on GitHub.
